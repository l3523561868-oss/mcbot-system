# 05 · 经验总结（27 条实测踩坑）

> 全部来自真实运行记录，每条都写清 **现象 / 根因 / 解法**。
> 编号 K01–K27 在其它文档里被引用，改编号会断链。

---

## 0. 先看方法论（比具体坑更值钱）

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | **先用探针确认事实，再改代码** | 这个项目 80% 的时间浪费在"猜服务端行为"，4 个探针脚本把猜测变成结论 |
| 2 | **不信接口返回值，回读状态判定** | 动作是异步的；`ok:true` 只代表"请求收下了" |
| 3 | **一个变量一次试验** | 同时改两处，出问题就不知道是哪处的功劳 |
| 4 | **先跑通最小闭环，再加功能** | 单 bot 进服 → 能说话 → 能走动 → 再谈多 bot 与 LLM |
| 5 | **日志即证据** | 每条关键路径都打一行可 grep 的标记（`协商成功`、`>> /login`、`[say] 已发`） |
| 6 | **症状和根因经常错位** | "控制台打不开"的根因可能是"僵尸 node 让启动脚本提前 exit" |
| 7 | **能脚本化的绝不在终端手敲** | 手机终端的软折行会静默破坏命令，甚至破坏 base64 载荷 |
| 8 | **改结构时先确认真源在哪** | 手机上的 `termux_deploy/` 是产物，改那里等于白改 |

## 1. 网络与本地请求

### K01 · 本机请求 `127.0.0.1` 返回 502
**现象**：`curl http://127.0.0.1:8801/state` 得到 502，但服务明明在跑。
**根因**：系统常驻 `HTTP_PROXY`，回环请求被代理接管。
**解法**：Python 侧 `urllib.request.build_opener(ProxyHandler({}))`；curl 加 `--noproxy '*'`。
适配器已全局使用绕代理 opener，这是**所有本地 HTTP 调用的前提**。

### K02 · `urllib Request()` 抛 ValueError 打断整个 handler
**现象**：某个 API 偶发 500，日志里是 ValueError。
**根因**：`Request()` 构造写在 `try` 外面，参数异常直接冒泡出请求处理链。
**解法**：构造移进 `try`；异常统一收敛成 `{ok:false, error:...}` 返回。

## 2. Python 模块与状态

### K03 · 场景报"至少需要 2 个 bot"
**现象**：控制台明明有 2 个 bot，场景却判定不足。
**根因**：`import console` 在另一个模块里拿到了**第二份模块实例**，`BOTS` 是空的那个。
**解法**：bot 列表当参数传，不在场景里重新 import；共享状态只保留一处。

### K04 · 控制台反复下发 goto，bot 来回弹
**现象**：bot 走到一半折返，来回震荡。
**根因**：每次下发都 `gotoVersion++`，把上一个 leg 取消了。
**解法**：单次下发 + 卡住时短跳（`jump 500ms`）脱困，不再重复下发同一目标。

## 3. 聊天与前端数据

### K05 · 聊天面板刷屏重复
**现象**：同一条消息显示多次，刷新也不消失。
**根因**：不同来源的聊天时间字段不统一（`at` / `ts`），按时间戳去重失效。
**解法**：改用 `seq`（单调递增）去重。**单调递增的序号永远比时间戳可靠。**

### K06 · 面板显示"连接失败"但服务正常
**现象**：`/api/state` 返回 401，前端把它当网络错误。
**根因**：开了 token 后回环客户端也被拦；前端没有 401 分支。
**解法**：`_authed()` 判 `client_address` 是回环即免 token；前端单独处理 401 → 弹令牌框。

## 4. 游戏内交互（协议层）

### K07 · 右键石碑后静默断线
**现象**：发 `ws_open` 后连接被断，无报错。
**根因**：代码里连发 4 个 `container_close`（windowId 0–3），服务端判定异常行为直接踢。
**解法**：`ws_open2`（去掉 `container_close`）→ 不再断线。

### K08 · 选点包发出但没传送
**现象**：`select_waystone` 返回成功，人没动。
**根因**：服务端要求**先右键打开界面**再选点，顺序错就无效。
**解法**：右键（`ws_open2`）→ 等 1.5s → `ws_select` → 传送成功。

### K09 · `goto_block` 永远"找不到 black_sharestone"
**现象**：按方块名找共享石碑始终失败。
**根因**：该方块的 `stateId` 存在但 `name` 为空（模组注册不完整）。
**解法**：不能按名找 —— 改用坐标 `goto` + `probe_block` 校验是否到了。

### K10 · 白天点床不设重生点
**现象**：点到床了，但重生点没变。
**根因**：原版规则，白天不能设重生点。
**解法**：等入夜再点（`wait_night_bed.py` 就是干这个的）。

### K11 · 0 级 bot 上线 5 分钟被怪打死
**现象**：`was slain by entity.primal.bear`，掉落 800 经验粒。
**根因**：默认开自动战斗 + "低等级长途赶路找经验"，0 级木剑无甲主动送死。
**解法**：新号首上必设 `COMBAT_OFF=1`、`XP_LOW_LEVEL=0`。
**教训：新号上线先关自动战斗和长途寻路，再谈功能测试。**

## 5. 依赖与补丁

### K12 · `npm ci` 失败：`vec3@^2.1.0` 不存在
**现象**：装依赖直接失败。
**根因**：上游 `package.json` 写错版本（实际 0.1.10），还混着 3 个未使用依赖，
`bin` 指向不存在的文件。
**解法**：备份 `.orig`，改成只含 3 个真依赖并按 lock 精确装
（mineflayer 4.39.0 / pathfinder 2.4.5 / minecraft-protocol 1.68.0 / prismarine-nbt 2.8.0）。

### K13 · `forge-live.mjs` 报通道表缺失
**现象**：启动即找不到 `channel-capture.json`。
**根因**：代码硬编码了原作者机器的绝对路径 `D:/AI玩家/AI/channel-capture.json`。
**解法**：优先读包内 `capture/`，找不到再回退旧路径。

### K14 · 被踢「服务器装了 NeoForge 但你没装」
**现象**：登录后立刻被踢，日志无异常。
**根因**：缺 `capture/channel-capture.json` → `capturedGroups()` 返回 null →
**静默不回** `neoforge:register` → 服务端判定你是原版客户端。
**解法**：补齐 1305 条通道表。判据是日志里有没有
`>> C->S neoforge:register（1305 通道）` 与 `✅ 协商成功`。
> 这类"缺文件不报错、只静默降级"的依赖最坑，`setup.sh` 已加资源自检。

## 6. 部署与进程管理

### K15 · `WinError 10048` 被误判成"地址失效"
**现象**：`make_deploy.py --serve` 报 10048，看起来像 IP 变了。
**根因**：**不是地址问题**，是 8000 已被上次的 `http.server` 占着。
旧脚本用 `bind()-close()` 预检、再交给 `http.server` 二次 bind，把"端口被占"误报成"换网段"。
**解法**：删掉预检，直接起服务；失败则报占用 PID 并自动顺延 8001…8009。
排查：`netstat -ano | findstr :8000` → `taskkill /PID <PID> /F`。

### K16 · 重连后卡 90 秒才登录
**现象**：断线几次后，每次重连都要等很久。
**根因**：`reconnects` 计数器只增不减 → 退避时间永久停在 90s。
**解法**：加 `STABLE_MS=60000`，spawn 后稳定 60s 就把计数清零。

### K17 · bot 发言只能成功一次
**现象**：第一次能发，之后全进待发队列。
**根因**：`authed` 只靠"聊天里出现『已成功登录』"置真；重连后那句不再出现 → 永远 false。
**解法**：12s 兜底（`if (!authed && bot.entity) authed = true`），日志会打
`[auth] 12s 内未收到「已成功登录」，按已登录处理`。

### K18 · 启动完立刻回到提示符，服务全没
**现象**：`start_session.sh` 一跑就退出，bot 也没了。
**根因**：`wait` 在 4 个子进程全死时**立即返回** → 触发 `EXIT` trap → 把刚启动的全杀。
**解法**：改心跳轮询 `while :; do sleep 5; pgrep -f forge-live.mjs || break; done`。

### K19 · 打开 Termux 却打不开控制台
**现象**：Termux 起来了，8900 拒绝连接。
**根因**：`if pgrep forge-live then exit 0` 写在起 `console.py` **之前**；
安卓留的僵尸 node 命中即退出 → console 根本没起。
**解法**：三个服务各自独立判断，"缺哪个起哪个"。

### K20 · 手机粘贴长命令报 `SyntaxError` / `zlib.error -3`
**现象**：一条 `python -c "...base64..."` 在手机上必失败。
**根因**：终端按屏宽（约 44 字符）软折行，在语句中间插入换行；
base64 载荷也被截断成非法流。
**解法**：**手机永不粘超一屏命令**，一律写成脚本文件（每行 ≤45 字符）；
zip 直传替代 base64 内联。

### K21 · `bash start.sh` → No such file
**现象**：明明解压了却说文件不存在。
**根因**：ZArchiver 二次解压，变成 `~/termux_deploy/termux_deploy/`。
**解法**：`cd ~/termux_deploy && mv termux_deploy/* . && rmdir termux_deploy`。

### K22 · `cp /storage/emulated/0/...` 找不到
**现象**：存储路径不存在。
**根因**：`termux-setup-storage` 回答了 n。
**解法**：重跑并答 **y**。

### K23 · `problem inflating chunk` + `Cannot read properties of undefined (reading 'value')`
**现象**：进服后解压区块失败，进程崩溃，控制台显示离线。
**根因**：`npm install` 把 `node_modules` 还原成上游原版，5 个补丁丢了。
**解法**：`node apply-patches.mjs`（输出"恢复 5 个补丁文件"）。
`setup.sh` / `start_session.sh` / `restart.sh` 都会自动补打。
判断补丁是否生效：`diff` 前先 `tr -d '\r'`（补丁文件是 CRLF），对比行号是否与上游差十几行。

### K24 · 看门狗把自己杀了
**现象**：日志停在"第 1 次重启"，之后什么都不发生。
**根因**：`--kill-match mock_bot.py` 这个字符串**本身就在看门狗自己的命令行里**，
按命令行子串匹配会匹配到自己 → `taskkill /F` 自杀。
**解法**：`find_pids()` 排除 `os.getpid()` 与 `os.getppid()`，启动时打印提示。
**自己写类似工具时同样要防这个。**

### K25 · 日志刷满 `BrokenPipeError: [Errno 32]`
**现象**：`console.log` 全是 Broken pipe，像崩了。
**根因**：**不是崩溃**。HTTP/1.0 每请求重开 TCP，手机端一页 200+ 请求，
浏览器刷新/关页/翻译插件会在 63 KB 页面传完前断开。
**解法**：`protocol_version="HTTP/1.1"` + `disable_nagle_algorithm=True` 复用连接；
`handle_one_request` 吞掉 BrokenPipe/ConnectionReset；顺带修了
"走代理时请求行是绝对 URI → 全部 404"的问题（统一 `urlparse(self.path).path`）。

### K26 · 手机进控制台首屏十几秒
**现象**：页面能开，但要等很久；右侧"服务器在线"永远"读取中"。
**根因**：① `/icons/` 对每个模组物品去外部源逐个拉，手机拉不到，每个等 3s 超时，
一次刷新几十个 → 首屏卡死；② `loadPlayers()/loadMap()` 固定取 `STATE.bots[0]`，
那只正在重连就直接 return。
**解法**：① 图标加**负缓存 + 60s 熔断**（失败过直接 404），实测 0.76s → 2ms；
② 改成"取第一只在线 bot"，全离线时显式显示"无在线 bot"。

### K27 · AuthMe：握手成功却一直重连
**现象**：日志显示 `✅ 协商成功`，但马上又断，循环。
**根因**：服务器装了 AuthMe，聊天里刷「请输入 /login <密码>」。
老代码只在 `spawn+3s` 发一次 `/login`，丢一次就永远未登录 → 服务端超时踢 → 重连 → 再踢。
**额外误判**：日志里的 `(第 500 次)` **不是重连次数**，是某个模组通道的计数（每 500 打印一次）。
**解法**：加登录守卫 —— `sendLogin()` 最多 3 次、间隔 ≥6s；
`checkAuthMe()` 从 `message` 与 `pushChat(system_chat)` 两条信道识别"催登录"提示并补发；
收到"密码错误"立即停手防临时封禁；每次 spawn 重置额度；`BOT_PW` 为空时显式报错。
