# 06 · 本地存档与局域网模式

> 目标：不连公服，直接让 bot 进自己的单人存档（"对局域网开放"），用于验证链路、测试动作、离线开发。
> 状态说明：本文的步骤基于代码能力与 Minecraft 单人 LAN 机制整理，**标 ⚠️ 的条目需你在本机实测确认**。

---

## 1. 能不能行：先看结论

| 问题 | 结论 |
|---|---|
| 技术上可行吗 | ✅ 可行。单人开 LAN 后本质是一个本地 integrated server |
| 仓库现在支持吗 | ⚠️ 支持了一半：`auth: "offline"` 已具备，`version` 已可覆盖（`MC_VERSION`），但**没有任何文档**，之前完全没提 |
| 和连公服的区别 | 无 AuthMe、无正版验证、端口每次变、世界必须一直开着 |
| 通道表还要吗 | **要**。本地 integrated server 同样执行 NeoForge 协商 |

---

## 2. 前置条件

| 项 | 要求 |
|---|---|
| 客户端 | 与存档一致的 **MC 1.21.1 + NeoForge**（或你自行适配的版本） |
| 存档 | 已能正常进入（排除模组/Java 问题） |
| 通道表 | 与该客户端一致的 `channel-capture.json`（见 [05-获取整合包与抓包.md](05-获取整合包与抓包.md)） |
| 端口 | LAN 开放时聊天栏会提示，例：`本地游戏已在端口 54321 上开启` |

> 只想先看控制台界面、不试真连接：直接用 `scripts/启动_演示模式.bat`（mock bot），不需要本文。

---

## 3. 步骤

### 3.1 在游戏里开放局域网

1. 进入世界，等完全加载；
2. `Esc` → **对局域网开放**（Open to LAN）；
3. 游戏模式随意，**允许作弊**建议开（方便 `/op`、`/tp`）；
4. 点"启动局域网世界"，记下聊天栏的端口号（每次开放都可能不同）。

> 单人 LAN 默认是离线验证，bot 用 `auth: "offline"` 可以直接进；不要用正版验证服务器的方式去配。

### 3.2 起 bot

```bash
cd src/bot

# 先在真终端里跑一次，方便看握手日志
# MC_VERSION 与存档一致；端口换成聊天栏给的那个
BOT_PW='' COMBAT_OFF=1 XP_LOW_LEVEL=0 BRIDGE_PORT=8801 \
  MC_VERSION=1.21.1 \
  node forge-live.mjs 127.0.0.1 54321 bot_local
```

| 变量 | 本地模式取值 | 说明 |
|---|---|---|
| `BOT_PW` | 留空 | 本地没有 AuthMe；留空后 3 秒会打印一行 `BOT_PW 为空，无法 /login`，**无害** |
| `MC_VERSION` | 与存档一致 | 默认 `1.21.1`；换版本必须显式给 |
| `BRIDGE_PORT` | `8801` | 控制台要连这个口 |
| `COMBAT_OFF` / `XP_LOW_LEVEL` | `1` / `0` | 避免新号乱跑送死 |

启动后日志里应看到：

```
>> /register（首次）或直接进入世界
>> C->S neoforge:register（N 通道）
✅ 协商成功
```

若第一条就是"示意样本"警告 → 通道表没换，回 [05](05-获取整合包与抓包.md)。

### 3.3 接控制台

`config/bots.example.json` → `src/console/bots.json`，把账号信息改成一致即可：

```json
[{
  "id": "bot-local",
  "name": "bot_local",
  "kind": "protocol",
  "base": "http://127.0.0.1:8801",
  "bridge_port": 8801,
  "enabled": true
}]
```

```bash
python src/console/console.py --port 8900
# 浏览器打开 http://127.0.0.1:8900
```

### 3.4 给 bot 权限（需要时）

单人世界里 bot 默认不是 OP，涉及 `/tp`、`/give` 等命令要先放权：

```
/op bot_local
```

### 3.5 校验

```bash
python scripts/doctor.py --verify
```

期望：`bot 在线 online=True authed=True`。
（本地没有 AuthMe，`authed` 由 12 秒兜底逻辑置真，见 `docs/05` 的 K17。）

## 4. 与「接入服务器」的差异

| 维度 | 本地存档 / LAN | 远程服务器 |
|---|---|---|
| 认证 | 离线验证 | 可能 AuthMe（`/login`） |
| 地址 | `127.0.0.1:<LAN 端口>`，**每次变** | 固定域名:端口 |
| 存活 | 世界必须一直开着；关世界即掉线 | 服务器常开 |
| 通道表 | 与客户端一致即可 | 必须与服务器一致 |
| 玩家可见性 | 只有你 | 公屏所有人可见，注意刷屏礼仪 |
| 权限 | 你是房主，可 `/op` | 通常无 OP |
| 版本 | 自己定，用 `MC_VERSION` 覆盖 | 必须严格匹配服务器 |

---

## 5. 已知限制（务必知道）

| 限制 | 说明 | 规避 |
|---|---|---|
| 世界必须运行 | 关掉世界/退出游戏，bot 立即掉线并进入重连循环 | 先停 bot 再关游戏 |
| 端口每次变 | 开 LAN 时随机分配 | 每次改命令行，或写进自己的启动脚本；**不要**把端口写死进仓库 |
| ⚠️ 暂停菜单 | 单人游戏打开暂停菜单会暂停 integrated server，bot 会卡住。开 LAN 后多数版本不再暂停，但**建议实测确认** | 保持游戏窗口在前台；或把游戏窗口放到另一桌面不最小化 |
| 无 AuthMe | `BOT_PW` 留空会有一行无害报错提示 | 忽略，或随意填一个值 |
| 皮肤拉取 | 默认会向 littleskin 拉皮肤，离线环境可能失败 | 失败仅影响外观，不影响进服 |
| 通道表仍需真实 | 12 条样本必被本地 integrated server 拒绝 | 按 [05](05-获取整合包与抓包.md) 抓包 |

## 6. 故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即退出，提示"示意样本" | 通道表还是仓库样本 | 换真实抓包；仅演示可 `ALLOW_SAMPLE=1` |
| `ECONNREFUSED 127.0.0.1:<port>` | 端口不对 / LAN 没开 / 世界已关 | 回游戏看聊天栏端口，重新开放 |
| 连上但立刻被踢 | 客户端与 bot 的 `MC_VERSION` 不一致，或通道表不匹配 | 对齐版本、重抓通道表 |
| `online:true` 但不动 | 可能是暂停菜单暂停了服务器 | 切回游戏窗口，确认世界在跑 |
| 命令无权限 | bot 不是 OP | 游戏内 `/op <name>` |
| 卡在 `/login` 循环 | 你误填了 `BOT_PW`，而本地没有 AuthMe | 清空 `BOT_PW` 重启 |
| 关游戏后日志刷重连 | 正常现象 | 先 `Ctrl-C` 停 bot |

---

## 7. 一句话总结

本地模式适合**验证与开发**：一条 `MC_VERSION=x node forge-live.mjs 127.0.0.1 <LAN端口> <名字>` 即可，
前提仍是**真实通道表**，且游戏世界要一直开着。

要做长期挂机，还是回到 [01-PC端部署](01-PC端部署.md) 或 [02-Termux安卓部署](02-Termux安卓部署.md)。
