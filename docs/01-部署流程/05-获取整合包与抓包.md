# 05 · 获取整合包与抓取通道表

> 这是**整条部署链上唯一必须人工完成的一步**，也是最容易卡住的一步。
> 做完这一步，AI 或脚本才能接管后面的启动与排错。

---

## 1. 为什么必须做

NeoForge 服务端在 `configuration` 阶段会要求客户端上报自己的**通道表**（实测环境约 1300 条）。
仓库里 `src/bot/capture/channel-capture.json` 只有 **12 条示意样本**，是给人看格式用的。

拿样本去连真服的结果：服务端判定"你没装 NeoForge"，直接踢。
现在 `forge-live.mjs` 启动时就会拦下来：

```
[!] 通道表只有 12 条，判定为仓库自带的“示意样本”。
    直接连任何真实 NeoForge 服务器都会被踢…
```

通道表的本质是**整合包指纹**（装了哪些模组、每个模组的通道与版本），
所以它既不能凭空生成，也不适合公开分发 —— 只能由你从目标环境抓。

---

## 2. 第一步：拿到与服务器一致的整合包

三条件必须**同时**满足，缺一个都握手失败：

| 条件 | 怎么核对 |
|---|---|
| MC 版本一致 | 服务器 MOTD/登录提示、服主公告；本项目默认 `1.21.1` |
| NeoForge（或 Forge）构建号一致 | 客户端启动器里显示的版本号，与服务器日志/公告对齐 |
| **模组集合一致** | 数量、名称、版本都要对得上（配置差异通常不影响握手） |

### 三条获取路径（按可靠度排序）

| 路径 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 服主提供整合包**（首选） | 直接要 CurseForge / Modrinth / packwiz 包，或他导出客户端实例 | 一次性对齐，最省事 | 取决于服主是否愿意 |
| **B. 用启动器导入公开整合包** | 在 Prism/CurseForge/Modrinth 启动器里搜同名整合包，选**与服务器相同版本** | 自己有控制权 | 需要知道包名与版本 |
| **C. 从已有客户端实例枚举** | 打开 `mods/` 目录，导出 `*.jar` 文件名清单 | 不用额外下载 | 只能核对，不能凭清单还原出包 |

> 拿到包之后**先离线进一次单人世界**，确认客户端自己能正常启动 —— 排除版本/Java 问题再谈抓包。

---

## 3. 第二步：抓通道表

### 3.1 官方客户端路径（推荐）

1. 用上面拿到的整合包启动客户端，登录目标服务器（走到"选择世界/进入"前即可）；
2. 在客户端侧记录 `configuration` 阶段客户端发出的自定义负载，重点是
   `neoforge:register`（或 `minecraft:register`）；
3. 解出每条记录的四要素：

| 字段 | 含义 | 取值 |
|---|---|---|
| `id` | 通道名 | `命名空间:路径`，如 `examplemod:sync_config` |
| `version` | 通道版本 | 字符串，常见是模组版本号或 `"1"` |
| `flow` | 方向 | `CLIENTBOUND` / `SERVERBOUND`（未知填 `null`） |
| `optional` | 是否可选 | `true` / `false` |
| `proto` | 阶段 | `PLAY` 或 `CONFIGURATION` |

4. 按 `src/bot/capture/channel-capture.json` 的数组格式落盘；
5. 顺手导出 `channel-specs.json`（`通道名 → {v: 版本, f: 0/1}`，未知留空也行）。

抓包工具怎么选（按可得性）：

| 工具 | 说明 |
|---|---|
| 启动器/模组自带的 debug 日志 | 最省事，部分整合包会打印通道注册 |
| 本地代理（mitmproxy 等） | 通用，需要配证书与端口转发 |
| 在客户端里加一个打印 `RegisterPayloadHandlerEvent` 的小模组 | 最准确，适合长期维护 |

### 3.2 应急路径：用"被踢载荷"反推通道名

当拿不到客户端、只想要个能跑的最小集合时：

```bash
node src/tools/probe.mjs <host> <port> <name>
# 会落盘 setup_failed.bin，里面是服务端列出的"缺失通道名"
```

- ✅ 能拿到**通道名清单**（服务端会逐条列出）；
- ❌ 拿不到版本号、方向、顺序；
- 结果：需要多轮试错，且容易触发服务器限流。

→ 只适合"实在没别的办法"，且**不要**对公共服务器高频重试。

### 3.3 同伴已有抓包

如果同一个服已经有人跑通了协议 bot，向他要 `channel-capture.json` **是最快的**。
注意：这份文件等于整合包清单，只应在可信范围内交换，**不要提交到公开仓库**。

## 4. 第三步：校验

```bash
# 0) 结构校验（不联网、不连服，只读本地文件）
node src/tools/channels.mjs validate src/bot/capture/channel-capture.json \
     --spec src/bot/channel-specs.json
# 期望：结构校验通过；条数不该是 12（那是样本）

# 换服时对比两套抓包
node src/tools/channels.mjs diff old.json new.json

# 1) 条数检查（会读取 capture/channel-capture.json）
python scripts/doctor.py

# 期望：通道表 PASS，条数与真实通道数接近（几百~上千）
```

```bash
# 2) 启动 bot，看握手
cd src/bot
BOT_PW='<口令>' BRIDGE_PORT=8801 node forge-live.mjs <host> <port> <name>
```

日志里必须出现这两行：

```
>> C->S neoforge:register（N 通道）      ← N 与你的文件条数一致
✅ 协商成功
```

```bash
# 3) 运行态复核
python scripts/doctor.py --verify
```

| 输出 | 含义 |
|---|---|
| `bot 在线 online=True authed=True` | 全通 |
| `online=False` | 还在握手/被踢，看日志 `kicked` |
| `online=True authed=False` | 通道过了，但 AuthMe 没登录 → 查 `BOT_PW` |

## 5. 常见失败对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即退出，提示"示意样本" | 还是仓库那 12 条 | 按本文替换；仅演示可 `ALLOW_SAMPLE=1` |
| 握手中途被踢，提示装 NeoForge | 通道表缺失或条数远少于服务端要求 | 重抓；确认包与服务器同版本 |
| `negotiation.failure.missing` 列出通道名 | 少通道 | 按列出的名字补齐，或重抓 |
| `modded_network_setup_failed` | 通道版本号不对 | 补 `channel-specs.json` 的 `v` 字段 |
| 条数够但仍被踢 | `flow`/`optional` 标错，或顺序错 | 优先用客户端原始顺序导出，别手工排序 |
| 换服后又不行 | 通道表与整合包绑定 | 每个服/每个包各抓一份，用 `MC_CAPTURE` 指定 |

多套通道表并存：

```bash
MC_CAPTURE=/path/to/serverA.json BRIDGE_PORT=8801 node forge-live.mjs <A> ...
MC_CAPTURE=/path/to/serverB.json BRIDGE_PORT=8802 node forge-live.mjs <B> ...
```

---

## 6. 合规与安全

1. 通道表是**整合包指纹**：可推断模组清单与版本，属服务器隐私，勿公开分发；
2. 抓包文件里可能夹带服务器地址、玩家名，提交前务必检查；
3. 本仓库 `.gitignore` 已排除 `logs/`、`_probe/`；自己新建的抓包目录也请加入忽略；
4. 用 `probe` 对公共服做迭代学习时，控制频率，避免被判扫描/限流。
