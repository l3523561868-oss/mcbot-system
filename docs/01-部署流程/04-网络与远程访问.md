# 04 · 网络与远程访问

> 控制台是"HTTP 服务 + 网页"，所以"手机能不能用"等价于"手机能不能访问到那个 8900"。
> 这一步走对，后面全顺；走错，会误以为是程序坏了。

---

## 1. 先明确访问模型

| 形态 | 后端在哪 | 前端在哪 | 要不要 token |
|---|---|---|---|
| PC 本机用 | PC | 同一个浏览器 | 不需要（回环免鉴权） |
| PC 跑、手机遥控 | PC | 手机浏览器 / APK | 同 WiFi/Tailscale 可不设；公网必须设 |
| 纯手机自洽 | 手机 Termux | 同一部手机的浏览器（`127.0.0.1`） | 不需要 |
| 旧手机当服务器 + 日常手机遥控 | 旧手机 | 日常手机 | 跨设备建议设 |

**控制台不能凭空监听服务器**：它必须借一个已登录的连接（bot 自己）才能拿到全服聊天。
所以"我把控制台暴露到公网，别人没装 bot 也能看聊天"是不成立的。

---

## 2. 三种连通方式

### A. Tailscale（推荐）

1. PC 与手机都装 Tailscale，登录**同一账号**；
2. 各自拿到 `100.x.x.x` 地址；
3. 手机浏览器开 `http://100.x.x.x:8900`。

优点：不动路由器、不要公网 IP、全程加密、4G/5G 与异地都能用。

### B. 同一 WiFi

1. PC 上 `ipconfig` 查局域网 IP（如 `192.168.1.50`）；
2. 手机连同一 WiFi，开 `http://192.168.1.50:8900`；
3. PC 防火墙放行 8900。

缺点：离开这个 WiFi 就断；部分路由器隔离客户端。

### C. 公网隧道（ngrok / cloudflared）

```bash
ngrok http 8900
# 或
cloudflared tunnel --url http://127.0.0.1:8900
```

**必须先设 token**：

```bash
python console.py --host 0.0.0.0 --port 8900 --token <长随机串>
```

> 重要判断：**Cloudflare 隧道解决不了"控制台打不开"**。
> 隧道只是代理，本地 `console.py` 没起来就是代理到死端口；而且 `cloudflared` 是额外常驻进程，
> 手机上更费电、更容易被回收。它唯一价值是异地遥控 —— 且必须先开 token。

## 3. 鉴权机制

```bash
python console.py --port 8900 --token <TOKEN> [--host 0.0.0.0] [--readonly] [--manage]
```

| 参数 | 作用 |
|---|---|
| `--token` | 非空则所有 `/api/*` 必须带 `X-Console-Token` 头或 `?t=` |
| `--host` | 默认 `127.0.0.1`；手机/远程必须 `0.0.0.0` |
| `--readonly` | 只读模式：非白名单动作在 `dispatch()` 入口直接拒绝 |
| `--manage` | 允许从网页启停 bot 进程（仅 PC 端；手机别开） |

规则细节：

- **首页 HTML 不鉴权**（否则浏览器进不来）；前端带令牌登录框，token 存 `localStorage`；
- **回环客户端免 token**：`client_address` 是 `127.0.0.1` 时直接放行，避免本机脚本被 401 卡住；
- 无 token 访问 `/api/*` 返回 401，前端会提示"需要访问令牌"而不是"连接失败"。

## 4. 只读模式（接高价值 bot 的第一道安全阀）

```bash
python console.py --port 8900 --token xxx --readonly
```

放行（查询类）：`state` `pos` `where` `players` `inv_list` `inv_detail` `armor_status`
`list_waystones` `scan_area` `ws_blocktypes` `help`

拒绝（改变世界/角色）：`move_to` `dig` `work` `follow` `say` `stop` `eat` `chat_cmd` 以及一切未列出的动作。

**在 `dispatch()` 入口拦截，不靠前端隐藏按钮**——前端隐藏只是 UI，绕过 API 一样能调。
实测 6 个危险动作全部返回"只读模式：xxx 不在白名单内"，6 个只读动作全部拿到数据。

界面配合：右上角显示「只读模式」，动作下拉只剩只读动词，「停止/进食」按钮隐藏。

## 5. 第三方接入的网络拓扑

| 方式 | 拓扑 | 优点 | 缺点 |
|---|---|---|---|
| A. 反向接入 `reporter.py` | 对方 **主动连** 控制台 | 天然穿 NAT、对方不用开端口 | 2 秒轮询延迟 |
| B. 隧道直连 | 控制台主动拉对方 `8801` | 延迟最低 | 对方要装 Tailscale |
| C. 游戏内语言层 | 走服务器公屏 `@bot 动词` | 零基础设施 | 公屏污染、100 字限制、有轮询延迟 |

反向接入原理：

```
console.dispatch() → INBOX 队列 → reporter 每 2s 领取
   → 翻译成对方 bot 的请求体 → 执行 → POST /api/result 回传
```

控制台侧这类 bot 的 `kind = reporter`，原始类型记在 `local_kind`。

## 6. 安全清单

- [ ] 公网暴露 = 必须 `--token`，且 token 足够长（≥32 字符随机）
- [ ] 不要把 8900 直接端口映射到公网裸奔；用 Tailscale Funnel / 反向代理
- [ ] 远程只做观察时用 `--readonly`
- [ ] 手机端不开启 `--manage`（否则网页能拉起进程，耗电且不可控）
- [ ] 仓库/截图里不留真实 token、口令、账号
- [ ] 遵循服务器规则：不刷屏、不破坏建筑、不违反挂机条款
