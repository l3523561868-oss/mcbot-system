# 01 · PC 端部署（Windows，从零到 bot 进服）

> 目标：一台 Windows 电脑上跑起 控制台 + 大脑 + 1~2 个协议 bot，浏览器能操作。
> 预计首次耗时 30–60 分钟，其中 `npm install` 与首次握手占大头。

---

## 1. 环境要求

| 项 | 最低 | 实测配置 | 备注 |
|---|---|---|---|
| 系统 | Windows 10 | Windows 11 / li352 | Linux/macOS 同样可行，脚本需改路径 |
| Python | 3.10+ | 3.13 | 控制台**只用标准库**，无需 pip 装包 |
| Node.js | 18+ | 22.x | `mineflayer` 需要；建议 LTS |
| 内存 | 2 GB 可用 | 11.8 GB 总 / 2.6 GB 可用 | 单 bot 约 150 MB，控制台 < 100 MB |
| 磁盘 | 1 GB | — | `node_modules` 约 300–600 MB |
| 网络 | 能连 MC 服务器 | — | 首次握手对丢包敏感，建议有线/WiFi 直连 |

`git` 可选（用于版本管理）；`npm` 随 Node 提供。

---

## 2. 目录与文件分工

```
<repo>/
├── src/console/     控制台（Python）+ 前端 index.html
├── src/bot/         协议 bot（Node）+ capture/ + patches/
├── src/tools/       探针 / 看门狗 / 导航
└── config/          示例配置
```

**真源两处**：控制台在 `src/console/`，协议客户端在 `src/bot/`。
手机端的 `termux_deploy/` 只是这两处的**打包产物**，不要直接改那边。

---

## 3. 安装步骤

### 3.1 装 Node 依赖

```bash
cd src/bot
npm install
node apply-patches.mjs        # 必须！见下
```

`npm install` 会把 `node_modules` 还原成上游原版，而本项目依赖 **5 个手工补丁**才能稳定运行。
`apply-patches.mjs` 负责把 `patches/` 下的完整文件覆盖回去，输出 `完成：恢复 5 个补丁文件。` 才算成功。

> 补丁做了三件事：关掉 bundle 缓存并插入坏包过滤（否则 keep_alive 被吞 → 30 秒超时踢）、
> NBT 解析空值保护、注册表加载容错。缺了会出现 `problem inflating chunk` 后进程崩溃。
> 详见 [06-协议层与NeoForge协商.md](../06-协议层与NeoForge协商.md)。

### 3.2 配置账号

```bash
cd config
cp bots.example.json   ../src/console/bots.json
cp brain.example.json  ../src/console/brain.json       # 不接 LLM 可跳过
cp providers.example.json ../src/console/data/providers.json   # 可选
```

`bots.json` 是 bot 注册表，字段含义：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 控制台内部唯一 ID（小写，别重复） |
| `name` | ✅ | 显示名，也是游戏内 `@名字` 的目标 |
| `kind` | ✅ | `protocol`（8801 那套）/ `client`（装模组的客户端）/ `reporter`（反向接入） |
| `base` | ✅ | bot 的 HTTP 地址，如 `http://127.0.0.1:8801` |
| `bridge_port` | 建议 | 本地端口，控制台用它判断进程是否在跑 |
| `account` / `password` | 建议 | 只给 GUI 启动器与手机脚本用；控制台本身不读 |
| `enabled` | 建议 | `false` 即隐藏 |

> `account/password` 只在"控制台帮你拉起 bot 进程"时才用到（`--manage` 或 GUI）。
> 控制台自己**不登录**，它只是 HTTP 客户端。

### 3.3 写 bot 的启动参数

协议 bot 靠环境变量配置，常用四个：

| 变量 | 建议值 | 作用 |
|---|---|---|
| `BOT_PW` | 你的 AuthMe 口令 | 进服后自动 `/login`；为空会显式报错 |
| `BOT_REG` | `0` | `1` 表示首次注册（会自动 `/register`），注册完改回 `0` |
| `COMBAT_OFF` | `1` | 关自动战斗。**新号必开**，否则 0 级木剑会被怪打死 |
| `XP_LOW_LEVEL` | `0` | 关"低等级长途赶路找经验"，否则 0 级会被拉着走一万多格 |
| `BRIDGE_PORT` | `8801` / `8802` | 每个 bot 一个桥端口 |

其余可选：`CHAT_MONITOR_OFF`、`WAYSTONE_EYE_OFF`、`RECONNECT_STAGGER`（重连错峰毫秒）、
`ANTI_AFK_OFF`、`DURABILITY_GUARD`、`COMBAT_RANGE`。

完整启动命令（一只 bot）：

```bash
cd src/bot
BOT_PW='你的口令' BOT_REG=0 COMBAT_OFF=1 XP_LOW_LEVEL=0 BRIDGE_PORT=8801 \
  node forge-live.mjs <服务器地址> <端口> <账号名>
```

两只 bot **必须错开 12 秒以上**启动：同 IP 同秒双登录容易触发服务端 `Connection throttled`。

## 4. 启动方式（四种，选一）

| 方式 | 命令 | 特点 |
|---|---|---|
| **GUI exe（推荐）** | 双击 `MC-Bot-GUI.exe` | 原生窗口，开窗全起、**关窗强制全停**；自动清残留 bot |
| 启动器 exe | `MC-Bot-Launcher.exe` | 无窗口，拉起后常驻；关启动器不停 bot |
| bat 脚本 | `scripts/启动全部.bat` | 与 exe 等价，便于改参数 |
| 手动 | 三个终端分别起 8801/8802/8900 | 排障时最直观 |

`MC-Bot-GUI.exe` 由 `src/console/build_gui.py` 打包（PyInstaller onedir）：
打包后 `_internal/` 目录必须跟着 exe 一起移动，否则起不来。

启动顺序（GUI 自动完成）：

```
清残留 forge-live 进程 → 起 bot1(8801) → 起 bot2(8802) → 起 console(8900) → 起 brain(8902) → 开窗口
```

bot 进服需 **60–100 秒**，这期间控制台显示"离线"是正常的。

## 5. 校验（四道关，逐条过）

| # | 检查 | 命令 / 位置 | 通过标准 |
|---|---|---|---|
| 1 | 补丁生效 | `cd src/bot && node apply-patches.mjs` | `完成：恢复 5 个补丁文件。` |
| 2 | 通道协商 | `grep -E "neoforge:register|协商成功" 日志` | 出现 `>> C->S neoforge:register（1305 通道）` 与 `✅ 协商成功` |
| 3 | AuthMe 登录 | 同上日志 | 出现 `[玩家系统] 已成功登录`，或至少在 `>> /login（第 1 次…）` 之后不再被踢 |
| 4 | 控制台联通 | 浏览器 `http://127.0.0.1:8900` → bot 卡片 | 状态"在线"、坐标/血量有数值、派 `state` 动作有回执 |

命令行快速探活（绕代理，见坑 K01）：

```bash
curl --noproxy '*' http://127.0.0.1:8801/state
```

返回 JSON 中 `online:true` 且 `position` 非 null 才算真的进服。`authed:true` 才代表能发言。

## 6. 换成别的服务器要改什么

本项目所有协议层细节是**针对 NeoForge 1.21.1 + 离线模式 + AuthMe** 调出来的。换服需要重做：

1. 用 `src/tools/probe.mjs <host> <port> <name>` 跑两阶段探针，看：
   - 服务端版本与是否要求 NeoForge 协商；
   - 是正版验证还是离线模式；
   - 客户端卡在哪个阶段、被踢时服务端给了什么载荷。
2. 若服务端是 NeoForge/Forge，必须重新抓一份 `capture/channel-capture.json`（用真客户端抓包），
   否则握手必失败。
3. 若是**正版验证**服务器，离线协议 bot 进不去 —— 这条路走不通，需要正版账号的会话密钥。
4. 改 `bots.json` 的地址与账号，重新起 bot。

## 7. 常见失败（PC 端）

| 现象 | 原因 | 处理 |
|---|---|---|
| `npm ci` / `npm install` 报 `vec3@^2.1.0` 不存在 | 上游 `package.json` 有错 | 本仓库已修正为 3 个真实依赖 + lock 锁版本 |
| `problem inflating chunk` + `Cannot read properties of undefined (reading 'value')` | 补丁没打 | `node apply-patches.mjs` |
| bot 一直重连、日志刷 `/login` | AuthMe 未登录 / 口令错 | 检查 `BOT_PW`；代码已有登录守卫，最多补 3 次 |
| 被踢「服务器装了 NeoForge 但你没装」 | 缺 `capture/channel-capture.json` | 补齐抓包文件，见 06 |
| 控制台"连接失败"但服务正常 | 本机请求走了系统代理 | `curl --noproxy '*'`；Python 侧 `ProxyHandler({})` |
| 点击动作后 bot 不动 | bot 实际离线（`online:false`） | 先读 `state` 再派动作，别盲派 |
| 两个 bot 互相抢目标 | 没走控制台租约 | 通过控制台派任务，租约 60s 独占 |

更多见 [../07-排错FAQ.md](../07-排错FAQ.md)。
