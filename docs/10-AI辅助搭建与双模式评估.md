# 10 · AI 辅助搭建与「服务器 / 本地存档」双模式评估

> 评估对象：本仓库当前状态（commit `cc15262`，tag `v1.0.0`）
> 评估时间：2026-10-24
> 结论口径：只认"仓库里有的东西"，不认"理论上能做"。

---

## 0. 结论（先看这三条）

| 问题 | 结论 | 一句话理由 |
|---|---|---|
| AI 能否照着本仓库在用户本地搭起来？ | **部分可行（约 70%）** | 环境安装、依赖、补丁、启动、排错可交给 AI；**整合包获取与通道抓包必须人工**，且文档没有机器可校验的步骤 |
| 是否同时支持「接入服务器」与「本地存档」两种模式？ | **只支持接入服务器；本地存档未支持** | 全仓库 0 处提到「本地存档 / 对局域网开放 / `online-mode`」（`局域网` 一词仅用于控制台访问场景）；`version` 写死 `1.21.1`，端口不做约定 |
| 会不会主动提醒用户下载对应整合包？ | **不会** | 只有 README 里一段静态警告 + 运行时"通道表 <100 条"提示；**没有清单、没有获取途径、没有校验** |

**总体判定：当前仓库是"完整的实现文档 + 可运行的源码"，但不是"AI 可独立完成的开箱即用安装包"。**
它默认读者已经有：目标服务器信息、能装模组的客户端、以及"抓包"这件事的技术能力。

## 3. 模式一：接入远程服务器

**判定：可行，但绕过不去两个人工步骤。**

AI 能独立完成的：

1. 检查并说明环境要求（Python / Node / Git）；
2. `npm install` + `node apply-patches.mjs`，并校验输出；
3. 生成 `bots.json` / `brain.json`（按用户给的账号信息）；
4. 起控制台与 bot，读日志断点（`协商成功` / `/login` / `kicked`）；
5. 用 `mock_bot.py` 先验证控制台链路，再切真服；
6. 按 FAQ 处理 502、端口占用、补丁丢失、握手失败等。

必须人工完成的：

| 步骤 | 为什么 AI 做不了 |
|---|---|
| 拿到与服务器一致的整合包 | 仓库不含任何整合包内容（有意脱敏），AI 无从得知目标服装了哪些模组 |
| 用真客户端进服并抓通道表 | 需要图形客户端 + 抓包工具 + 一次性操作，AI 无法在无 GUI 环境完成 |
| 提供账号与 AuthMe 口令 | 属凭证，不应出现在对话或仓库里 |
| 确认服务器是否允许挂机 | 规则问题，需人判断 |

→ 因此 AI 辅助搭建的**真实覆盖率约 70%**，且这 70% 集中在"环境与代码"，30% 卡在"数据与凭证"。

## 4. 模式二：本地存档（单人 / 对局域网开放）

**判定：代码层面具备可能性，仓库层面 = 未支持。**

### 4.1 技术上为什么"可能"

- bot 用 `mineflayer` + `auth: "offline"`（`forge-live.mjs:245/249`，`host` + `auth: "offline"`）；
- 单人世界"对局域网开放"后本质是一个本地 integrated server，监听 `127.0.0.1:<随机端口>`；
- 模组加载器与模组集与客户端一致，因此**通道握手逻辑可以复用**。

### 4.2 当前挡路的 5 个具体缺口

| # | 缺口 | 影响 | 证据 |
|---|---|---|---|
| L1 | 没有任何 LAN / 单人说明 | 用户不知道要"对局域网开放"、端口每次变化、世界必须保持运行 | 全仓库 0 处提及 |
| L2 | `version` 写死 `"1.21.1"` | 换成 1.20.1 等存档直接连不上 | `forge-live.mjs:248` |
| L3 | 端口靠命令行参数，无"从日志/进程自动发现" | 每次开 LAN 端口都变，需手工改脚本 | `start.sh` 等写死 `mc.example.com:25565` |
| L4 | 皮肤拉取、AuthMe 守卫按"公服"假设写 | 本地世界无 AuthMe，`sendLogin` 不会触发（无害）但 `fetchSkinFromLittleSkin` 会打无用外部请求 | `forge-live.mjs:243`、`486` |
| L5 | 通道表仍与客户端实例绑定 | 本地存档同样需要正确的通道表，否则 integrated server 会拒绝 | 同 §3 |

### 4.3 如果现在就要跑通（临时手工步骤，未写入文档）

1. 用与存档相同的 1.21.1 + NeoForge 客户端打开世界 → **对局域网开放**，记下聊天栏给出的端口；
2. `cd src/bot && node forge-live.mjs 127.0.0.1 <端口> <任意用户名>`；
3. 若被踢，说明通道表不对，需要按捕获流程补；
4. 控制台 `bots.json` 里把 `base` 指向 `http://127.0.0.1:8801` 即可。

> 这套步骤**目前只是推断**（未实测），且第 2 步没有写进任何文档 —— 这正是要补的缺口。

## 5. AI 代搭：还缺哪些"给机器看"的东西

现有文档是**给人看的教程**（叙事 + 截图 + 经验），AI 读得懂但缺少确定性与自校验。要让 AI 真正"一键搭完"，需要补 7 项：

| # | 缺什么 | 具体形态 | 价值 |
|---|---|---|---|
| A1 | 环境体检 | `scripts/doctor.py`：版本、命令存在性、端口占用、依赖完整性、补丁哈希、通道表条数 → 逐项 PASS/FAIL 与退出码 | AI 可在 10 秒内定位失败点 |
| A2 | 结构化安装入口 | `scripts/install.ps1`（Windows）/ `install.sh`（Linux/macOS）：按顺序执行并可 `--check` 只体检 | 把 15 条人工命令压成 1 条 |
| A3 | 模式化配置 | `config/mode.server.json` 与 `config/mode.local.json` 模板 + `version`/`port`/`auth` 参数化 | 双模式开箱切换 |
| A4 | 运行时版本声明 | `.nvmrc`、`runtime.txt`（或 `pyproject.toml` 的 `requires-python`） | 避免"版本不同导致的玄学" |
| A5 | 机器可读成功判据 | `doctor --verify`：握手成功、`/state` 返回 `online:true`、控制台 200 → 输出 JSON | AI 可循环校验直到达标 |
| A6 | 整合包引导 | `docs/` 新增"如何获取与服务器一致的整合包"（向服主要 modlist / packwiz manifest / 客户端目录 `mods` 列表），并给校验清单 | 解决当前最大人工断点 |
| A7 | 抓包生成工具 | `src/tools/capture-channels.mjs`：利用被踢载荷里的通道名 + 客户端抓包文件，输出合规 `channel-capture.json` | 把"抓包"从玄学变成一条命令 |

## 6. 关于"主动提醒下载整合包"

**现状：不构成"主动提醒"。**

| 现有机制 | 位置 | 触发时机 | 够不够 |
|---|---|---|---|
| 文档静态警告 | `README.md` §2、`docs/01/01` §3.1.5 | 人主动读文档时 | ❌ 不主动 |
| 启动时条数检查 | `forge-live.mjs`（`<100 条` 打印提示） | bot 启动 | ⚠️ 只提醒"这是样本"，不提醒"去哪里拿整合包" |
| 握手失败被踢 | 服务端提示 | 已连服 | ❌ 事后，且提示是服务端的，不是本项目的 |

缺的三件事：**① 整合包来源指引；② 启动前的阻断式检查（而不是打印一行继续跑）；③ 与服务器 modlist 的比对**。

## 7. 缺失项清单（按优先级）

### P0 · 不做则"AI 自助搭建"不成立

| 项 | 影响 | 建议 |
|---|---|---|
| 整合包获取指引缺失 | 用户/ AI 拿不到通道表来源，卡在第一公里 | 新增 `docs/01-部署流程/05-获取整合包与抓包.md`：modlist 索取、packwiz/curseforge manifest、客户端 `mods/` 目录枚举、校验和比对 |
| 无 LAN / 本地存档支持 | 双模式只剩一个 | 新增 `docs/01-部署流程/06-本地存档与局域网.md` + `version`/`port` 参数化 |
| 通道表样本会误导 | 用户照样本启动，误判"代码坏了" | 改为**启动前置校验**：条数 < 阈值直接退出并打印解决路径（`ALLOW_SAMPLE=1` 可强行继续） |
| 无环境体检 | AI 无法判断失败点是环境还是数据 | `scripts/doctor.py` |

### P1 · 明显降低成功率

| 项 | 建议 |
|---|---|
| 无 Windows 一键安装 | `scripts/install.ps1`（含 `--check` / `--yes`） |
| 版本未声明 | `.nvmrc` + `requires-python` |
| 成功判据不可机读 | `doctor --verify --json` |
| 抓包无自动化 | `src/tools/capture-channels.mjs` |

### P2 · 体验优化

| 项 | 建议 |
|---|---|
| 多版本支持 | `MC_VERSION` 环境变量替代写死的 `1.21.1` |
| 多服务器并存 | `bots.json` 增加 `version` 字段，按 bot 生效 |
| 首次运行引导 | `console.py` 首次无 `bots.json` 时给出 3 行配置向导 |

## 8. 补齐后的目标状态（验收口径）

一个用户 + 一个 AI 助手，在只有"服务器地址 + 账号"的前提下，应能：

1. `git clone` → `scripts/install.ps1 --check`（全绿）；
2. 按 `05-获取整合包与抓包.md` 拿到整合包 → 一条命令生成通道表 → `doctor` 校验条数；
3. `install.ps1` 起服务 → `doctor --verify --json` 返回 `{"handshake":"ok","online":true,"console":200}`；
4. 若失败，`doctor` 直接给出"下一步做什么"，不需要读 10 篇文档。

当前距离这个状态：**缺 4 项 P0 + 4 项 P1**，预估 1.5–2 人日（不含实测真服）。

## 9. 一句话总结

**现在的仓库能教会人（和 AI）"这套东西怎么工作、怎么排错"，但还不能让 AI 独立完成"从零到进服"。**
最短补齐路径是：整合包指引 + 通道表前置校验 + `doctor` 体检 + 本地存档/局域网文档。
