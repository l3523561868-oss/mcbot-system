# 03 · PC 端控制台：构建方案与实现

> 一个 Python 文件（后端）+ 一个 HTML 文件（前端）+ 一个适配层，把"多个异构 bot"变成"一个可派任务的界面"。
> 设计原则：**零第三方依赖、单文件前端、不信接口返回值**。

---

## 1. 分层与职责

```
index.html（单页，67 KB，无构建步骤）
   │  fetch /api/*
   ▼
console.py  ── poll_loop 每 2s 拉每只 bot 的 /state，聚合进 STATE
   │           dispatch() 做三件拦截：只读白名单 / 目标租约 / 未在线
   ▼
adapters.py ── Adapter 子类：ProtocolBot / ClientBot / ReporterBot
   │           build_action() 把统一语义翻译成各家私有请求体
   ▼
bot HTTP 桥（8801 / 8780 / 外部 reporter）
```

为什么这样分：

| 问题 | 做法 | 原因 |
|---|---|---|
| 协议 bot 只有十几个动作，客户端 bot 有 100+ 动作名 | 只对控制台暴露**统一语义**（最小公倍数） | 不统一就得为每种 bot 写一套 UI |
| 各家请求体不同 | `build_action()` 收口在适配器 | 接新 bot 只加一个子类 |
| 动作是异步的 | 不信返回值，回读 `state` | 返回 `ok:true` 只代表"请求收下了" |
| 前端要零依赖 | 原生 JS + CSS，单 HTML | 改一行刷新就生效，手机也能直接打开 |

## 2. 统一语义（控制台对外只有这些动作）

| 语义 | 协议 bot 映射 | 客户端 bot 映射 |
|---|---|---|
| `move_to(x,z)` | `{type:"goto",x,z,range}` | `mc_act goto` |
| `dig(block?)` | `{type:"goto_block",match}` 或 `{type:"dig"}` | `mc_act dig` |
| `work(mode)` | `{type:"work",mode}` | `mc_act work` |
| `follow(player)` | `{type:"follow",player}` | `mc_act follow` |
| `say(text)` | `{type:"say",text}` / `{type:"cmd","/me …"}` | `mc_act chat` |
| `stop` / `eat` | 同名 `{type:"stop"}` / `{type:"eat"}` | 同名 |
| `equip` / `move_slot` / `use_item` | 背包类，见 §6 | 同名 |
| `waystone` / `warp_to` / `list_waystones` | 传送类 | 同名 |

协议 bot 原生动作共 **104 个**（`forge-live.mjs` 的 HTTP switch），控制台只挑需要的那部分做语义映射；
未映射的可以通过只读白名单或 `RAW` 直接透传。

**发言的坑**：公屏聊天在部分服务端会被部分聊天插件因"无签名"丢弃，所以 `say` 备了 `/me`
通道；适配器里用 `say_mode` 切换。

## 3. HTTP API 一览

### GET

| 路径 | 说明 |
|---|---|
| `/` | 单页前端（不鉴权） |
| `/api/state` | 全量聚合：bots[]（坐标/血量/饥饿/等级/Ping/日志）+ 聊天 + 语言流 + 任务 |
| `/api/scenarios` | 内置互测场景列表 |
| `/api/inbox` | 反向接入 bot 的待执行队列 |
| `/api/providers` | LLM 提供商列表（含用量） |
| `/api/ai` | AI 配置读取 |
| `/icons/<name>` | 物品图标（缺失走负缓存，见 §7） |

### POST

| 路径 | 请求体 | 说明 |
|---|---|---|
| `/api/act` | `{bot, verb, args}` | 派动作（唯一的主要入口） |
| `/api/say` | `{bot, text, mode}` | 以某 bot 身份发言，`mode` = `say` / `me` |
| `/api/ai_cmd` | `{bot, text}` | 自然语言任务：LLM → `{reply, actions[]}` → 依次执行 |
| `/api/bots` | bot 定义 | 注册新 bot，写回 `bots.json` |
| `/api/bots/remove` `/start` `/stop` | `{id}` | 删除 / 启停（需 `--manage`） |
| `/api/scenario` | `{name}` | 跑一个互测场景 |
| `/api/chat` | `{source, who, text}` | 外部上报聊天（第三方接入） |
| `/api/report` | `{id, state, chat[]}` | reporter 上报状态与聊天 |
| `/api/result` | `{id, result}` | reporter 回传执行结果 |
| `/api/providers*` | — | 增删改默认、拉模型列表、查余额 |

鉴权：`--token` 非空时，`/api/*` 需 `X-Console-Token` 头或 `?t=`；回环地址豁免。

## 4. bot 间语言层（`@bot 动词 参数`）

任何一只 bot 的聊天里出现 `@<名字或id> <动词> <参数>`，控制台捕获并路由：

```
@Bot-B move_to 120 -30     → 让 Bot-B 走到 (120,-30)
@Bot-B work log            → 砍树
@Bot-B follow Steve        → 跟随玩家
@Bot-B say 收到            → 让它说话
```

- 动词必须在 `VERBS` 白名单内，参数由 `_parse_args()` 解析（坐标、模式、玩家名）；
- 目标不存在 / 动词不合法 / 被租约拒绝 → 记入「语言流」面板并回失败原因；
- 执行成功后自动让被指挥的 bot 回执 `[Bot-A] move_to ok`，指挥方在游戏里就能看到；
- 要扩动词：只改 `console.py` 的 `VERBS` 与 `_parse_args()`。

为什么用游戏内文本而不是私有信道：**两个人（或两个 bot）都能在游戏里看见对话**，
可审计、可复现，且不需要额外网络。代价是公屏可见 + 100 字限制。

## 5. 冲突控制：目标租约

```python
LEASES = {}   # target_key -> {bot, ts}
```

- key = `verb + 坐标`；有效期 60 秒；
- 两个 bot 抢同一目标，第二个直接被拒，避免互相推挤；
- 租约只解决"同一目标"，不同目标同时跑仍可能挡路 —— 需要人约定路线。

## 6. 背包与装备

`inv_list` 返回：`items` / `hotbar(36-44)` / `quickBarSlot` / `offhand(45)` / `armor(5-8)`。

| 交互 | 动作 |
|---|---|
| 拖拽到主手/副手/盔甲 | `equip`（盔甲有类型白名单 head/torso/legs/feet；胸甲槽可放鞘翅/背包） |
| 拖到背包格 | `move_slot` |
| 单击 → 主手，右键 → 副手 | `equip` |
| 「使用主手/副手」 | `use_item`（`activateItem`） |

两个必须知道的限制：

1. **主手是热栏选中格的镜像**，不是独立存储 —— 换主手会改变热栏选中位；
2. 饰品栏（部分模组的扩展装备栏）在协议层读不到，界面上仅占位。

## 7. 前端实现要点

| 要点 | 做法 | 为什么 |
|---|---|---|
| 单文件 | 内联 CSS/JS，无打包 | 手机端直接打开、改完刷新即生效 |
| 轮询 | 2s 一次 `/api/state` | 简单可靠；动作本身异步，轮询足够 |
| 战术地图 | Canvas 按 `map_slice` 数据重建俯视图 | 协议 bot 能看到方块，不需要渲染 |
| 物品图标 | 服务端代理 `/icons/<name>`，**负缓存 + 60s 熔断** | 原来逐个去外部源拉，手机拉不到 → 每个等 3s 超时 → 首屏卡死。实测 0.76s → 2ms |
| 在线人数 | 取"第一只在线 bot"的视角 | 原来固定取 `bots[0]`，它一重连就整个面板失效 |
| 令牌登录 | 401 时弹输入框，token 存 `localStorage` | 首页不鉴权才能进来 |
| 聊天去重 | 按 `seq`（单调递增）而不是时间戳 | 不同来源时间字段不一致（`at`/`ts`） |
| 长页面 | 单页分区（非路由） | 手机浏览器切页会丢失 WebSocket/轮询状态 |

面板清单（自上而下）：BOT 列表 · 发言 · 全服聊天 · 战术地图 · 服务器在线 · 背包 · 派任务 ·
互测场景 · 语言流 · 运行状态 · 接入新 BOT · 操作日志 · API 提供商。

## 8. 只读模式与安全闸门

`--readonly` 打开后，`dispatch()` 在最前面拦：不在 `RO_VERBS` 里的动作直接返回
`只读模式：xxx 不在白名单内`。

- 白名单 = `state` + `adapters.RAW_READONLY`（查询类）+ `say`（说话不伤 bot）；
- `chat_cmd` 即使在只读下也禁 —— 它能执行任意服务器指令；
- **为什么先只读**：对方那只 bot 是唯一资产（高等级、死亡掉经验），
  且背包解析当时不稳。只读接入能在零风险下验证"控制台 ↔ 真 bot"是否成立。

## 9. 反向接入（NAT 后的第三方 bot）

对方机器上跑 `reporter.py`，主动连控制台：

```bash
python reporter.py --console https://<控制台> --token <token> \
    --id alice-bot --name 爱丽丝bot \
    --local http://127.0.0.1:8801 --kind protocol
```

链路：`dispatch → INBOX 队列 → reporter 每 2s 领取 → 翻译成 bot 请求 → POST /api/result`。

好处：对方不用开端口、不用公网 IP；代价是 2 秒轮询延迟。

## 10. GUI 与打包

`gui.py`（pywebview 原生窗口）：

- **开窗口 = 全起**：清残留 → 起 bot1/bot2 → 起 8801/8802 → 起 8900/8902 → 开窗口；
- **关窗口 = 强制全停**：先 terminate 自己拉起的进程，再用 PowerShell 兜底清任何
  `forge-live.mjs` 残留。

打包：

```bash
python src/console/build_gui.py
# 等价于：
# pyinstaller --onedir --windowed --name MC-Bot-GUI --icon icon.ico \
#   --collect-all webview --collect-all pythonnet --collect-all clr_loader \
#   --add-data "index.html;." --add-data "bots.json;." gui.py
```

两个打包坑：

1. 必须 **onedir**（不是 onefile）：onefile 的 bootloader 有 job 限制，
   子进程 `CREATE_BREAKAWAY_FROM_JOB` 会 `WinError 5`；
2. `_internal/` 必须跟着 exe 一起移动，否则缺 DLL 起不来。

> 注意：exe **无法直接转成 APK**。手机端是另一条路（WebView 套壳），见
> [04-移动端控制台.md](04-移动端控制台.md)。

## 11. 接一个全新 bot 要改什么

1. 写 `adapters.py` 子类，实现 `build_action(verb, args)`，注册到 `ADAPTERS`；
2. `bots.json` 加一条：`{id, name, kind, base, enabled}`；
3. 刷新页面，卡片自动出现；
4. 用 `curl` 对它的桥发一次 `state`，确认能通再派动作。

不需要动前端、不需要动 `console.py`。
