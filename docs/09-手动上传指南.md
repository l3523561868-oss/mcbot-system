# 09 · 手动上传到 GitHub（完整步骤）

> 面向"仓库已经在本地建好、只需要推上去"的情况。
> 本仓库路径示例：`D:\AIchat\AIdailychat\WorkBuddy-work\mcbot_github_repo`
> 目标仓库名：`mcbot-system`（Public）

---

## 0. 上传前检查（约 3 分钟，别跳过）

打开 Git Bash（或 PowerShell），执行：

```bash
cd /d/AIchat/AIdailychat/WorkBuddy-work/mcbot_github_repo
git status --short          # 应该没有输出（工作区干净）
git log --oneline -1        # 应该有一条提交
git ls-files | wc -l        # 文件数，正常 85 左右
du -sh . --exclude=.git     # 体积，正常 1~2 MB
```

### 0.1 敏感信息复查（公开仓库必做）

```bash
# 口令 / 密钥
git grep -niE "password|passwd|api[_-]?key|secret|token" -- . | grep -v "example\|README\|SECURITY\|<"
# 真实地址 / 账号残留
git grep -niE "aspireworld|yuan_bot|universal|muyiyang|序苑|25159|10\.102\." -- .
# 常见密钥前缀
git grep -nE "sk-[A-Za-z0-9]{20,}|ghp_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}" -- .
```

三条命令**都应无输出**。有输出就先把该文件改成占位符再提交：

```bash
# 改完重新提交
git add -A && git commit -m "chore: 脱敏"
```

### 0.2 确认 `.gitignore` 生效

```bash
git check-ignore -v src/console/bots.json   # 有输出 = 已被忽略（正确）
git ls-files | grep -E "bots\.json|\.env$|node_modules"   # 应无输出
```

## 1. 路线 A：命令行 + 网页建空仓库（推荐）

### 1.1 在网页上建一个空仓库

1. 浏览器打开 <https://github.com/new>（已登录）。
2. **Repository name** 填 `mcbot-system`。
3. **Description** 可填：`Minecraft 多 Bot 控制系统：协议 bot + 网页控制台 + 安卓 Termux 部署`。
4. 可见性选 **Public**。
5. **不要**勾选 "Add a README file"、"Add .gitignore"、"Choose a license" ——
   仓库必须完全为空，否则首次推送会因历史不一致被拒。
6. 点 **Create repository**。页面会显示一段 `git remote add origin ...` 的提示，先不要关。

### 1.2 准备访问凭证（GitHub 已不支持账号密码推送）

1. 打开 <https://github.com/settings/tokens> → **Generate new token (classic)**。
2. Note 填 `mcbot-upload`，Expiration 选 30 天（够用即可）。
3. Scopes 只勾 **`repo`**（公开仓库推送最小权限；要操作 Actions 再加 `workflow`）。
4. 生成后**立刻复制**（形如 `ghp_xxxxxxxx`），关掉页面就看不到了。

> 也可以用自己的 SSH key（`ssh-keygen` → 把 `~/.ssh/id_ed25519.pub` 贴到
> <https://github.com/settings/keys>），后续 remote 用 `git@github.com:用户名/mcbot-system.git`，
> 就不用每次输 token。

### 1.3 本地配置身份与远程地址

```bash
cd /d/AIchat/AIdailychat/WorkBuddy-work/mcbot_github_repo

# 如果从没配过 git 身份（配过可跳过）
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"

# 关联远程仓库（把用户名换成你自己的）
git remote add origin https://github.com/<你的用户名>/mcbot-system.git

# 核对
git remote -v
git branch -M main        # 确保分支叫 main
```

### 1.4 推送

```bash
git push -u origin main
```

弹出凭证窗口时：

| 字段 | 填什么 |
|---|---|
| Username | 你的 GitHub 用户名 |
| Password | **粘贴 1.2 生成的 token**（不是账号密码） |

Windows 会把凭证存进「凭据管理器」，之后不用再输。命令行若提示
`Support for password authentication was removed`，说明填的是账号密码 —— 重来一次填 token。

成功输出应类似：

```
Enumerating objects: 88, done.
...
To https://github.com/<用户名>/mcbot-system.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

### 1.5 验证

```bash
# 方式一：命令行
curl -s https://api.github.com/repos/<用户名>/mcbot-system | grep -E '"name"|"private"|"size"'

# 方式二：直接开网页
start https://github.com/<用户名>/mcbot-system
```

网页上应能看到：README 正常渲染、根目录有 `LICENSE`、`docs/`、`src/`、`assets/`。

## 2. 路线 B：纯网页上传（不装 Git）

适合"完全不想碰命令行"。限制：单文件 ≤25 MB、每次最多 100 个文件、不能保留空目录。

### 2.1 建仓库（这次要勾 README）

1. <https://github.com/new> → 名称 `mcbot-system` → Public → **勾选 Add a README file** → Create。
2. 进入仓库 → **Add file → Upload files**。

### 2.2 分批拖拽

把本地目录**按文件夹分批**拖进上传区（拖文件夹会保留层级）：

| 批次 | 拖什么 | 说明 |
|---|---|---|
| 1 | `LICENSE`、`.gitignore`、`.gitattributes`、`README.md`、`SECURITY.md` | 根文件；README 会覆盖自带的那个 |
| 2 | `docs/` 整个文件夹 | 含 9 篇文档 |
| 3 | `config/`、`scripts/`、`assets/` | 配置模板、bat、截图 |
| 4 | `src/console/` | 控制台代码 |
| 5 | `src/bot/`（不含 `node_modules`，本仓库本来就没有） | 协议客户端 |
| 6 | `src/deploy/`、`src/android/`、`src/tools/` | 部署脚本与工具 |

每批底部 Commit message 填一句（如 `docs: 添加部署文档`）→ **Commit changes**。

> 注意：网页上传不会执行 `.gitignore` 过滤，拖之前自己确认没带 `node_modules`、
> `bots.json`、`.env`、日志。macOS 的 `.DS_Store` 也删掉。

## 3. 路线 C：GitHub Desktop（图形化，介于两者之间）

1. 装 [GitHub Desktop](https://desktop.github.com/) 并登录。
2. **File → Add local repository** → 选 `mcbot_github_repo` 目录。
3. 右上角 **Publish repository**。
4. 取消勾选 "Keep this code private"（即公开）→ 仓库名填 `mcbot-system` → **Publish**。
5. 之后每次改动：左下填 Summary → **Commit to main** → 顶部 **Push origin**。

## 5. 后续更新流程

```bash
cd /d/AIchat/AIdailychat/WorkBuddy-work/mcbot_github_repo

git status                      # 看改了什么
git add -A
git commit -m "docs: 补充 XX 说明"
git push                        # 已设 upstream，不用再带 origin main
```

**提交前每次都跑一遍第 0.1 节的敏感扫描**——这是唯一容易反复出错的地方。

打版本标记（可选）：

```bash
git tag -a v1.0.0 -m "首个公开版本"
git push origin v1.0.0
# 然后在网页 Releases → Draft a new release → 选 v1.0.0
```

## 6. 常见错误与处理

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `remote origin already exists` | 之前加过 remote | `git remote set-url origin <新地址>` 或 `git remote remove origin` 后重加 |
| `Updates were rejected because the remote contains work...` | 建仓库时勾了 README，远端已有提交 | `git pull --rebase origin main` 后再 `git push`；或删仓库重建（不勾任何初始化文件） |
| `Support for password authentication was removed` | 用了账号密码 | 改用 Personal Access Token（1.2 节） |
| `Authentication failed` 反复弹窗 | 凭证缓存了错的密码 | Windows「凭据管理器」→ 删除 `git:https://github.com` → 重推 |
| `error: src refspec main does not match any` | 还没有提交，或分支叫 master | `git log` 确认有提交；`git branch -M main` |
| `RPC failed; HTTP 413` / 推送中断 | 单次数据量大 / 网络不稳 | 重试；或 `git config http.postBuffer 524288000`；或改用 SSH |
| `Filename too long` | Windows 路径长度限制 | `git config --global core.longpaths true` |
| 大量 `LF will be replaced by CRLF` 警告 | 换行符自动转换 | 无害；本仓库 `.gitattributes` 已固定 `.sh` 为 LF |
| 推送后中文文件名乱码 | 网页端显示正常，命令行 `git status` 转义 | `git config --global core.quotepath false` |
| 网页上图片不显示 | 路径大小写或未上传 `assets/` | 检查 `assets/console-main.png` 是否在仓库里 |
| 误传了密钥 | — | **立即**在对应平台吊销该密钥，再 `git filter-repo` 清历史并强推；仅删文件不够 |

## 7. 撤回与改可见性

| 需求 | 操作 |
|---|---|
| 公开改私有 | 仓库 → Settings → 最下 **Danger Zone** → Change repository visibility → Make private |
| 删除仓库 | Settings → Danger Zone → Delete this repository（需输入仓库名确认） |
| 只删某个文件 | 网页打开文件 → 右上垃圾桶 → Commit；历史里仍可查到（敏感文件必须轮换密钥） |
