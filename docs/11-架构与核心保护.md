# 11 · 架构分析与核心保护机制

> 面向"继续加功能但别把主业搞崩"的问题。分两部分：**现状诊断**（哪层在承担什么、哪里会连锁）
> 和 **保护机制**（核心契约层 + 附加模块 + 守卫脚本，已落地）。

---

## 1. 现状分层

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层   index.html（单文件：DOM + 状态 + 内联 JS，1400 行）      │
├──────────────────────────────────────────────────────────────┤
│ 应用层   console.py（HTTP/轮询/语义翻译/租约/鉴权/进程管理）      │
│          adapters.py（protocol/client/reporter 三类适配）        │
├──────────────────────────────────────────────────────────────┤
│ 契约层   core/contract.mjs（事件总线 + 动作注册表，零依赖）  ★新  │
│          core/addons.mjs（附加模块加载器，异常隔离）        ★新  │
├──────────────────────────────────────────────────────────────┤
│ 协议层   forge-live.mjs（~5100 行：握手伪造 + 注册表注入 +       │
│          寻路/工作/战斗/背包/传送 + HTTP 桥 104 动作）           │
├──────────────────────────────────────────────────────────────┤
│ 依赖层   mineflayer / minecraft-protocol / prismarine-*         │
│          ↑ 由 patches/ 覆盖 5 个文件（握手、NBT、注册表、背包）   │
├──────────────────────────────────────────────────────────────┤
│ 数据层   capture/*.json（通道表）· channel-specs.json           │
│          bots.json / brain.json（配置，不入库）                  │
└──────────────────────────────────────────────────────────────┘
```

**关键事实**：

- 协议层是**单体**：握手、注册表、AI 行为、桥接全部在一个文件里；
- 契约层是本次新增的**唯一稳定边界**：零依赖、只暴露 `on / emit / registerAction / dispatchAction`；
- 依赖层被**运行时改写**（`apply-patches.mjs` 覆盖 node_modules），这是最脆弱的一环。

## 3. 核心运行机制

### 3.1 一条 bot 的生命周期

```
读 capture/channel-capture.json          ← 缺/样本 → 直接 exit 2
      ↓
mineflayer 连接 → login → configuration
      ↓ 服务器发 neoforge:register(空)
回传 1303 条通道（按抓包的 proto/flow/version/optional 原样编码）
      ↓ 服务端 modded_network_setup_failed 或 协商成功
协商成功 → frozen_registry 同步（2.7 万物品）→ PLAY
      ↓
spawn 事件 ──► coreEmit(SPAWN)
      ↓
HTTP 桥 :8801  (/state 读取；POST 派 104 个动作)
      ↓
每秒 coreEmit(TICK)；聊天/死亡/断开各自 emit
```

### 3.2 控制台 ↔ bot 的数据流

```
index.html --2s 轮询--> console.py /api/state --HTTP--> 每个 bot 的 /state
                     \--> /api/act  --> adapters.py 翻译 --> bot POST {type:...}
```

控制台**不缓存**状态，只做转发与聚合；bot 掉线时 `online:false`，页面显示"离线"。

## 4. 耦合风险清单（带实测证据）

| # | 风险 | 表现 | 证据 |
|---|---|---|---|
| R1 | **协议层单体**：5100 行里同时有握手、注册表、寻路、战斗、GUI、桥 | 改一行 flow 编码，可能影响 100+ 动作 | 本次修 `capturedGroups()` 默认 flow，直接决定能否进服 |
| R2 | **全局可变状态**：`global.__regMaps` / `__frzCount` / `__bdNetSync` | 一次解析失败污染全局，后续所有注册表读不到 | 修 `payload-dump` 目录缺失后，2.7 万物品才注入成功 |
| R3 | **运行时改写依赖**：`patches/` 覆盖 node_modules | `npm install` 一次全部丢失 → 崩在 `problem inflating chunk` | 每次装依赖都要 `apply-patches` |
| R4 | **静默失败**：大量 `try {} catch {}` 吞错 | 失败点被吞，最终表现为"连上了但进不去" | `frozen_registry` 解析失败被吞 → 卡在 configuration |
| R5 | **配置缺失无兜底**：`bots.json` 不存在时控制台空白 | 用户以为坏了 | 旧版控制台显示"无在线 bot" |
| R6 | **页面单文件 1400 行**：DOM、状态、协议混写 | 改一个按钮可能影响轮询渲染 | 本次加输入框需同时改模板、CSS、JS 三处 |
| R7 | **前后端字段隐式契约**：`/state` 的字段名靠约定 | bot 端改名 → 页面静默空白 | 多个字段同时被 index.html 与 adapters 消费 |
| R8 | **环境变量爆炸**：20+ 个开关（`COMBAT_OFF`/`XP_GUARD`/`MC_*`/`ALLOW_SAMPLE`…） | 拼错不报错，行为悄悄不同 | `XP_LOW_LEVEL=0` 曾被误当开关（其实是阈值） |

### 4.1 已经发生过的连锁（真实案例）

| 触发点 | 连锁 | 最终症状 |
|---|---|---|
| 改 flow 默认值 | 3 条 starterkit 通道编码错误 → 服务端判 flow 缺失 → 踢 | 握手成功却进不去 |
| `payload-dump/` 目录不存在 | 转储抛 ENOENT → 整个 registry 分支被 catch 吞掉 | 无限卡 configuration |
| `npm install` 后忘记打补丁 | bundle 缓存 + 坏包 → keep_alive 被吞 → 30s 超时 | 反复重连、日志"离线" |
| 把端口填进 Host 字段 | 连 `54815:54815` → ECONNREFUSED | 以为服务器挂了 |

**结论**：当前最大的连锁源不是"功能太多"，而是**核心层没有边界**——协议层既当基础设施又当业务，
任何一处改动都在同一命名空间里扩散。

## 5. 核心边界规则（R1–R6，硬约束）

| 规则 | 内容 | 谁来保证 |
|---|---|---|
| **R1** | `core/` 零依赖、零业务，只能被 import，不能 import 业务 | `core-guard` 依赖方向检查 |
| **R2** | 新功能一律写 `addons/*.mjs`，通过 `ctx` 接入 | 评审 + addons/README |
| **R3** | 需要新事件/字段 → 先改 `contract.mjs` 并 bump `CONTRACT_VERSION`，再写 addon | 契约版本号 |
| **R4** | 核心文件的任何改动必须 `core-guard --update -m "原因"` | 守卫脚本（改动即失败） |
| **R5** | addon 异常不得冒泡到核心（`emit` 内隔离，错误计入 `contractStatus`） | 契约层实现 |
| **R6** | addon 不得 `import "../forge-live.mjs"` | 依赖方向检查 |

## 6. 保护机制（已实现）

### 6.1 三件套

| 文件 | 职责 | 大小 |
|---|---|---|
| `src/bot/core/contract.mjs` | 事件总线（6 个事件）+ 动作注册表 + **能力服务** + **状态贡献** | 181 行，零依赖 |
| `src/bot/core/addons.mjs` | 扫描 `addons/*.mjs`，逐个 `setup(ctx)`，单个失败不影响其他 | 54 行 |
| `src/tools/core-guard.mjs` | SHA-256 指纹 + 依赖方向 + 体积守卫 | 150 行 |
| `src/bot/core/codec.mjs` | 线格式纯函数（varint/utf/注册表载荷解码） | 76 行 |
| `src/bot/core/registry.mjs` | 注册表存储（RegistryStore）+ 注入（injectIntoPrismarine） | 108 行 |
| `src/tools/selftest.mjs` | 21 项核心自检（20 秒内） | 210 行 |

接线点（核心只加了 6 处，均在生命周期固定位置）：

```
forge-live.mjs
  ├─ import { EVENTS, emit, dispatchAction } from "./core/contract.mjs"
  ├─ bot.on("spawn")      → emit(SPAWN)
  ├─ bot.on("death")      → emit(DEATH)
  ├─ bot.on("end")        → emit(DISCONNECT, {reason, lived})
  ├─ bot.on("message")    → emit(CHAT, {text})
  ├─ setInterval 1s       → emit(TICK)
  └─ 桥 switch 的 default → dispatchAction(...)  ← 未知动作先问 addon

# 能力服务（契约 1.1.0）：核心把"原语"暴露出去，addon 只写策略
registerService("bot",    { get, goto, say, isAuthed, isOnline })
registerService("items",  { findXp, useXp })
registerService("config", { xpSpot, xpLowLevel, version })
# /state 由 addon 贡献字段：contributeState("xpguard", () => ({...}))
```

### 6.2 用法

```bash
# 校验（提交前 / CI）
node src/tools/core-guard.mjs

# 确实要改核心：显式签入 + 记录原因（写进 CORE.lock）
node src/tools/core-guard.mjs --update -m "修复 flow 编码"

# 机器可读
node src/tools/core-guard.mjs --json
```

**保护范围**：`src/bot/core/` 下所有 `.mjs` **自动纳入**（新增核心文件不会因忘记登记而漏保护），
另加 `forge-live.mjs`、`console.py`、`adapters.py`、`index.html` 与三份通道表数据。

输出示例：

```
[guard] 核心保护检查
  ✗ 核心文件被改动（需 --update -m "原因"）：
      src/bot/core/contract.mjs  126→128 行 (+2, core)
  ✗ 依赖方向违规：
      src/bot/addons/foo.mjs → ../forge-live.mjs：addon 不得直接 import 核心业务文件
```

### 6.3 写一个附加功能（不动核心）

```js
// src/bot/addons/my-feature.mjs
export default function setup(ctx) {
  ctx.on("spawn", ({ bot }) => ctx.log("进来了：" + (bot.entity?.position ?? "?")));
  ctx.registerAction("my_action", async (a) => ({ ok: true, echo: a }));
}
```

重启 bot 即生效，日志出现 `[addon] 已加载 my-feature`。

### 6.4 隔离性实测

```
[addon] 已加载 example-gamemode
[addon] 共加载 1 个附加模块

# 故意让第一个订阅者抛错
[contract] addon@spawn: addon 故意抛错
第二个订阅者仍执行, n= 7
status: {"listeners":2,"actions":1,"emitted":1,"errors":1}
```

→ 插件错误被计数并记录，**核心与其它插件继续运行**。

## 7. 后续迁移路线（把单体拆薄）

按风险从低到高，每一步都可单独验证：

| 阶段 | 动作 | 收益 | 风险 |
|---|---|---|---|
| ① 已完成 | 契约层 + addons + guard | 新功能不再进核心 | 低（只加接线） |
| ② **已完成** | 经验守卫迁到 `addons/xp-guard.mjs`：策略在插件，原语（goto/say/items）由核心以 service 暴露 | 核心 **-47 行**，策略可单独开关/替换 | 中（已用桩服务验证注册与状态） |
| ③ | 把注册表解析拆成 `core/registry.mjs`（纯函数：buf → 名称表） | 可单测，去掉全局变量 | 中高（涉及 2.7 万物品注入） |
| ③ **已完成** | 注册表解析 → `core/codec.mjs` 纯函数；存储/注入 → `core/registry.mjs`；`global.__regMaps/__itemMap/__bdNetSync/__frzCount` 全部改模块内变量 | 可单测、无全局共享状态 | 中（已用真实 prismarine 注册表验证） |
| ④ | 桥接路由表化：`{type: handler}` 抽到 `core/bridge.mjs` | 动作与协议解耦 | 高 |
| ⑤ | 握手层 `core/handshake.mjs`（通道编解码纯函数） | 换服只改数据不改代码 | 高 |

> 原则：**每次只搬一块，搬完立刻用 core-guard 签入并跑一次真实进服**。

## 8.5 保障体系：三道闸门

| 闸门 | 命令 | 拦住什么 |
|---|---|---|
| **守卫** | `node src/tools/core-guard.mjs` | 核心被悄悄改动、依赖方向违规、核心膨胀 |
| **自检** | `npm --prefix src/bot test`（或 `node src/tools/selftest.mjs`） | 线格式/注册表/契约/装载 逻辑退化 |
| **隔离** | 运行时自动生效 | 单个 addon 抛错拖垮核心 |

自检覆盖（21 项，实测 21/21）：

```
线格式   varint/utf 往返·截断·越界
注册表   载荷解码（正常/畸形/截断）· RegistryStore · 注入（假对象 + 真实 prismarine 1.21.1）
契约     emit 隔离·priority·once·dispatch·同名保护·服务冻结·状态字段隔离
装载     两个 addon 加载 · xpguard 动作注册 · 状态字段出现
守卫     core-guard 退出码 0
```

> 建议顺序：改代码 → `npm test` → `core-guard` → 真服跑一次。

## 9. 一句话总结

**核心现在只负责"连上、解析、转发"，加功能不再改核心。**
边界由三样东西保证：零依赖的契约层、只许向下的依赖规则、以及改核心必须显式签入的守卫脚本。
