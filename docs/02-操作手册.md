# 02 · 操作手册（日常运维）

> 只讲"怎么开、怎么关、怎么看、怎么修"。部署见 `01-部署流程/`。

---

## 1. 四个服务，各自负责什么

| 服务 | 端口 | 挂了会怎样 | 恢复方式 |
|---|---|---|---|
| `console.py` | 8900 | 浏览器打不开控制台（**bot 还在跑**） | 重启 console 即可 |
| `brain.py` | 8902 | AI 指令退回规则解析 | 重启 brain |
| `forge-live.mjs` ×1 | 8801 | 控制台显示 bot1 离线 | 重启对应 bot |
| `forge-live.mjs` ×2 | 8802 | 控制台显示 bot2 离线 | 同上 |

**最容易误判**：控制台打不开 ≠ bot 挂了。反过来也一样。

## 2. 启停

### PC

| 操作 | 方式 |
|---|---|
| 全起 / 全停 | `MC-Bot-GUI.exe` 开窗 / 关窗（关窗强制杀 `forge-live.mjs`） |
| 只起控制台 | `python src/console/console.py --port 8900` |
| 只起大脑 | `python src/console/brain.py --port 8902` |
| 只起一只 bot | 见 01 文档的启动命令（含环境变量） |

### 手机 Termux

| 操作 | 命令 |
|---|---|
| 全套启动（推荐） | `sh ~/termux_deploy/restart.sh` |
| 增量启动（缺哪个补哪个） | `sh ~/termux_deploy/start_session.sh` |
| 只跑一只 bot | `SINGLE_BOT=1 sh ~/termux_deploy/restart.sh` |
| 停止 | `sh ~/termux_deploy/stop.sh` |
| 体检 | `sh ~/termux_deploy/check.sh` |
| 更新 | `sh ~/termux_deploy/update.sh` |
| 停自启 | `touch ~/termux_deploy/NO_AUTOSTART` |

## 3. 看状态

### 控制台（首选）

打开 8900，看：

- bot 卡片的圆点（绿=在线）、坐标、血量/饥饿、等级、Ping、最近说话；
- 「全服聊天」是否在滚动（**不滚动 = 连接有问题**，不是没人说话）；
- 「服务器在线」人数（全 bot 离线时会显式显示"无在线 bot"）。

### 命令行

```bash
# bot 决策桥
curl --noproxy '*' http://127.0.0.1:8801/state

# 控制台状态聚合
curl --noproxy '*' http://127.0.0.1:8900/api/state

# 手机端一次体检
sh ~/termux_deploy/check.sh
```

`check.sh` 输出：进程数（含看门狗）、控制台 HTTP 码、8801/8802 桥 HTTP 码、
每只 bot 的最近断开/被踢/登录记录、日志行数。

> **日志行数**隔一分钟再看一次：涨=进程活着；不动=卡住。

### 日志位置

| 端 | 文件 |
|---|---|
| PC | 控制台窗口输出；GUI 的 `_launcher_log/`；bot 各自 stdout |
| 手机 | `~/termux_deploy/console.log`、`brain.log`、`bot-8801.log`、`bot-8802.log`、`watchdog.log` |

## 4. 常见操作对照

| 想做的事 | 怎么做 |
|---|---|
| 让 bot 走到某坐标 | 控制台「派任务」选 `move_to`，传 `x z`；或 `@bot move_to 120 -30` |
| 让 bot 说话 | 「发言」区选 bot → 输入 → 发公屏 / 发 `/me` |
| 让 bot 砍树/挖石 | `work` + mode（`log` / `stone` / `patrol` / `stop`） |
| 让 bot 跟随玩家 | `follow` + 玩家名 |
| 让 bot 停下 | 派 `stop`，或点卡片上的「停止」 |
| 更换 AI 提供商 | 「⚙ API 提供商」页；可增删、设默认、查余额与用量 |
| 用自然语言下达任务 | 聊天区底部输入框 → `POST /api/ai_cmd`（有 key 走 LLM，无 key 走关键词规则） |
| 接入新 bot | 「接入新 BOT」填 id / name / kind / base → 注册 |
| 看 bot 背包 | 「🎒 背包」页；拖拽装备，单击到主手，右键到副手 |

## 5. 看门狗

| 端 | 脚本 | 行为 |
|---|---|---|
| 手机 | `watchdog.sh` | 每 30s 探 8900，连续 2 次非 200 → 重启 `console.py`，写 `watchdog.log` |
| PC（通用） | `src/tools/watchdog.py` | 探活任意 URL，连续失败 N 次后重启指定命令；支持 `--dry-run` / `--once` |

PC 版要点：

```bash
python src/tools/watchdog.py \
  --url http://127.0.0.1:8801/state --expect online \
  --cwd src/bot --cmd 'node forge-live.mjs <host> <port> <user>' \
  --kill-match forge-live.mjs --cooldown 120
```

- `--cooldown` 默认 **120 秒**：协议 bot 进服要 60–100 秒，判断太早会把正在启动的进程再杀一次；
- `--kill-match` 按命令行子串杀进程，**已排除自身 pid**（见坑 K24）。

## 6. 常见误区（实测确认）

| 误解 | 实际 |
|---|---|
| 关自启 = 关 bot | 不是，只影响**下次**打开 Termux；当前在跑的不受影响 |
| 关掉 Termux，小部件起的 bot 也会停 | 不会，小部件版用 `setsid` 脱离了会话 |
| 控制台打不开 = bot 挂了 | 反了，控制台挂了 bot 还在 |
| 更新完要手动重启 | 不用，`update.sh` 末尾自动 `restart.sh` |
| 手机上要一直连着 PC | 不用，只有更新那几分钟需要 PC 提供 zip |
| 看到 `BrokenPipeError` 就是崩溃 | 不是，是浏览器在 63 KB 页面传完前断开（刷新/关页/翻译插件） |
| 日志里 `(第 500 次)` 是重连次数 | 不是，那是某个模组通道的计数（每 500 打印一次） |
| 服务器在线人数 0 = 服务器没人 | 可能是所有 bot 都离线，控制台没数据源 |

## 7. 每天的常规动作

1. 早上看一次控制台：bot 在线？坐标正常？聊天在滚？
2. 手机是否还在 Termux（会话模式下关了就全停）；
3. 电量/温度（长期插电注意散热）；
4. 发现离线 → `sh restart.sh`，看三条成功判据；
5. 若反复离线 → `check.sh` 看被踢原因，再查 `07-排错FAQ.md`。
