# 00 · 项目总览

## 1. 项目是什么

**MCBot** 是一套 Minecraft 多机器人控制系统。它不启动游戏客户端，而是用 Node 的
`minecraft-protocol` / `mineflayer` 在**协议层**直接与服务端握手，因此：

- 内存占用约 150–500 MB / bot（真客户端需 4–6 GB）；
- 无需显卡、无需渲染，可在旧安卓手机的 Termux 里跑；
- 一个进程可以完全无人值守，用 HTTP 桥对外暴露状态与动作；
- 用 Python 写的控制台把"多个 bot"聚合成一个可派任务、可互相指挥、可看全服聊天的网页。

目标场景：让 2 个以上机器人账号在同一个 NeoForge 服务器里长期在线，由人或 LLM 通过一个网页调度。

## 2. 演进过程（为什么长成现在这样）

| 阶段 | 时间 | 关键动作 | 留下的东西 |
|---|---|---|---|
| ① 概念验证 | 10-15 | 想复刻别人已有的"AI 玩家"系统，发现核心代码只在对方机器上 | 结论：**运行时无法接管，只能自己造** |
| ② 协议层攻坚 | 10-18 | 用探针摸清服务端协商行为，补出上千条通道表，bot 成功进服 | `forge-live.mjs`、`capture/`、`patches/`、探针工具 |
| ③ 控制台 MVP | 10-18 | 统一"协议 bot / 客户端 bot"两套接口，做单页控制台 | `console.py`、`adapters.py`、`index.html` |
| ④ 桌面化 | 10-19 | 打包成 GUI exe，打开即全起、关闭即全停 | `gui.py`、`launcher.py`、打包脚本 |
| ⑤ 去 PC 化 | 10-20 | 整套搬进安卓 Termux，实现"零电脑"24h 托管 | `src/deploy/` 全套脚本、`make_deploy.py` |
| ⑥ 打磨 | 10-21 ~ 10-24 | 前端性能、鉴权、AuthMe 登录守卫、看门狗、多 bot 错峰 | 27 条踩坑记录、首屏从十几秒降到 1s |

**最重要的一条结论**：项目能成立的前提是**拿到服务端的通道协商细节**（实测环境约 1300 条通道定义）。
在拿到之前，任何"朴素离线连接"都会卡在 `configuration` 阶段或被 13ms 内踢掉。

## 4. 数据流（一次"派任务"的完整链路）

```
前端点「下发」
  → POST /api/act {bot, verb, args}
  → console.py dispatch()
     ├─ 只读模式检查（READONLY 白名单）
     ├─ 目标租约检查（verb+坐标 60s 独占）
     ├─ adapters.build_action() 翻译成 bot 原生请求
     └─ POST http://127.0.0.1:8801/ {type:"goto", ...}
  → forge-live.mjs 执行（pathfinder / 挖方块 / 聊天）
  → 2s 后前端轮询 GET /api/state 回读坐标与血量，判定成败
```

**关键设计**：不信接口返回值，只回读 `state` 判定结果。协议层动作是异步的，接口返回 `ok:true` 只代表
"请求收下了"，不代表"做到了"。

## 5. 端口与进程约定

| 端口 | 进程 | 绑定 | 谁来连 |
|---|---|---|---|
| 8900 | console.py | `127.0.0.1`（默认）/ `0.0.0.0`（手机模式） | 浏览器、手机、第三方 |
| 8902 | brain.py | 同上 | console.py |
| 8801 | forge-live.mjs #1 | `127.0.0.1` | console.py |
| 8802 | forge-live.mjs #2 | `127.0.0.1` | console.py |
| 8000~8009 | `make_deploy.py --serve` | LAN IP | 手机 `update.sh` |

端口被占时的顺延逻辑：下载服务 8000→8009；其余端口直接报错并打印占用 PID 排查方式。

## 6. 验收标准（项目自定的"算成功"）

1. 控制台能打开，bot 显示**在线**，坐标/血量/饥饿实时刷新；
2. 从网页下发 `move_to`，bot 在 5 秒内实际位移（用回读坐标验证）；
3. 两个 bot 能同时在服，且能通过 `@bot 动词` 互相指挥；
4. 关掉 PC，手机侧仍能进服、仍能发言（2026-10-20 实测通过）；
5. bot 断线后能自动重连，且重连后仍能发言（AuthMe 登录守卫生效）。
